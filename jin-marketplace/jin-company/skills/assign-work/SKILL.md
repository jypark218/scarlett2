# 팀에 일 맡기기

요청을 받으면 총괄 비서 → 팀장 → 팀원 순서로 일을 내려보내고, 결과를 작업 보드로 정리한다.

## 조직도

| 팀 | 팀장 | 팀원 |
|---|---|---|
| 총괄 | chief-of-staff (총괄 비서) | 각 팀장 |
| 게임 개발팀 | game-lead | game-designer, unity-dev, game-ui-engineer, narrative-writer |
| UI 포트폴리오/취업준비팀 | career-lead | case-study-writer, portfolio-builder, recruiting-scout |
| 데라디 가게 비주얼 디렉팅 TF | visual-director | brand-identity-designer, space-print-designer, visual-content-maker |
| 개인 브랜딩팀 | brand-lead | content-marketer, brand-designer, service-planner, revenue-analyst |

## 진행 순서

1. `work-guide` 스킬로 작업 가이드를 읽어 관련 팀의 정보가 채워져 있는지 확인한다. 비어 있는 필수 항목만 한 번에 묻는다.
2. 요청이 한 팀 안의 일이면 그 팀장에게 바로 맡긴다. 여러 팀에 걸치면 chief-of-staff에게 맡긴다.
3. 팀장은 직접 만들지 않고 팀원에게 나눠 준다. 서로 기다릴 필요 없는 일은 동시에, 앞 결과가 필요한 일은 순서대로 진행한다.
4. 사용자가 "시안 먼저"라고 하면 각 담당이 시안 단계에서 멈추고 보고한다. "바로 완성"이면 끝까지 진행한다.
5. 크레딧·비용이 드는 단계(이미지·영상 생성, 인쇄 발주, 유료 도구)에서는 멈추고 사양을 보여 준 뒤 허락을 받는다.
6. 팀장이 검수한 뒤 아래 작업 보드로 보고한다.

## 작업 보드 형식

```
## 작업 보드 (YYYY-MM-DD)

### 맡긴 일
- [팀] 작업명 — 담당 / 요청자

### 진행 중
- [팀] 작업명 — 담당 · 2/3단계

### 확인 대기
- [팀] 작업명 — 담당 · 결과물 링크 · 확인 필요 항목

### 완료
- [팀] 작업명 — 담당 · 완료 시각
```

나중에 사무실 앱을 만들 때 이 보드를 그대로 읽어 왼쪽 작업 보드에 띄울 수 있도록 형식을 바꾸지 않는다.

## 팀 간 연결

- 게임 개발팀 마일스톤 결과물(화면, GIF, 영상) → 커리어팀 케이스 스터디 소재
- 커리어팀 케이스 스터디 → 개인 브랜딩팀 콘텐츠 소재
- 데라디 TF 결과물 → 사용자 허락 시 포트폴리오·브랜딩 소재

연결이 가능한 결과물이 나오면 보드의 "확인 필요"에 제안으로만 적고, 다른 팀에 자동으로 넘기지 않는다.
